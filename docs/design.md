# 数据与调度约定

## Case 与预报场

CSV 每行一个评估案例，`case_id` 在实验内唯一，`storm_id` 是用户提供的稳定台风标识。
台风名称、海盆不改变全球模型输入。两个案例在起报时间、预报时长、输出间隔、源文件内容、
模型和计算设置完全相同时，共用 `_forecasts/` 中的结果；各自保留案例元数据和相对文件链接。
不同预报时长不做跨任务裁剪复用。程序按起报时间排序执行，但汇总表保持原 CSV 顺序。

源文件和权重按 SHA-256 标识。运行指纹还记录源代码、数值库版本和计算设备，
因此修改文件内容不会因文件名相同而错误复用。ERA5 初始场只缓存一个在内存中。
同一次执行期间，不应修改模型或输入文件。

## 原文贪婪算法

每个目标时效独立采用 24、6、3、1 小时的降序贪婪分解，再合并相同前缀。
例如 18 小时为 6+6+6，24 小时为 24，30 小时为 24+6，56 小时为 24+24+6+1+1。
不能让 24 小时预报来自四次 6 小时模型，也不能从 56 小时的输出再调用 1 小时模型构造 57 小时预报。
57 小时的正确链是 24+24+6+3。

执行图中每个节点记录 `(lead, parent, model_step)`。按时效升序执行，使用引用计数释放不再作为
父节点的全球状态。逐时写入输出，内存不会随着保存的时次数线性增长。
默认每 6 小时输出到 168 小时共 28 个时效，执行 28 次，与官方 24/6 小时迭代示例一致。
这只是算法测试案例，实际预报时长由用户每次提供。

## 输入

程序只需要起报时刻的全球 ERA5：地面 `msl,u10,v10,t2m`；高空 `z,q,t,u,v`。
气压层必须可选择出 `1000,925,850,700,600,500,400,300,250,200,150,100,50 hPa`。
纬度从 90 到 -90，经度从 0 到 359.75，间隔 0.25 度。

支持 `time/valid_time`、`level/pressure_level`、`lat/latitude`、`lon/longitude`，
负经度会转换后排序；压力坐标支持 Pa 与 hPa。输入的纬度、经度必须为一维规则网格。
按请求时间精确选一帧。多余维度只有长度为 1 时自动去除；多成员、多个 expver 等有歧义输入报错。
不会隐式插值、拼接 expver、合并多个文件或补缺失值。

场变量使用模型原生单位：气压 Pa，温度 K，风 m/s，位势 m²/s²，比湿 kg/kg。
单位缺失或不一致直接报错；例如位势高度不能未经转换冒充位势。
NumPy 数组只存在内存中，不输出 NPY。

本地 NetCDF 可以包含多个时刻，但每个起报时间必须唯一。
用户提供的本地文件不需要另建元数据；自动下载的文件带有程序生成的请求和校验 sidecar。

## 输出与恢复

`surface.nc` 中变量维度为 `(valid_time, latitude, longitude)`；
`upper.nc` 为 `(valid_time, level, latitude, longitude)`，level 使用真实 hPa 值。
`forecast_reference_time` 为标量 UTC 起报时间，`lead_time` 为整数小时，
`valid_time = forecast_reference_time + lead_time`。初始场不写入预报时间序列。

NetCDF 使用 float32、无损压缩，时间坐标使用 float64 的 epoch 小时数。
写入期间使用 `.partial` 文件，文件关闭并重命名后才将 manifest 标记为 complete。
恢复会检查 manifest、文件可读性、大小、变量和时效；不以输出文件存在作为成功依据。

`--resume` 要求同一实验的清单、配置和代码相同。输入、权重或依赖改变也不会复用旧案例结果。
更改实验参数时使用新 experiment 名称。未完成任务从起报场重跑，不恢复中间推理状态。
失败 case 写入错误并继续后续任务；共享预报失败不会在同一批次反复重试。

同一实验加进程锁，避免多个运行同时写文件。首版不实现多 GPU 或后台任务服务。
